# New Body — R&D Contributor Quest (HTML5 Game)

> A gamified, fully-automated recognition layer for the New Body surrogate
> infrastructure project. Contributors earn **XP** from real repository activity,
> climb **100 levels**, and unlock **status ranks, repo privileges, and prizes**
> — with zero manual bookkeeping.

---

## 1. Premise

New Body is an open R&D effort. To keep contributors motivated and to surface
the most engaged builders, every meaningful repository action is translated into
XP by an event pipeline. An HTML5 client renders each contributor's journey as a
progressible quest: a 100-rung ladder of research tiers, each rung granting a
reward. The loop is **automatic** — you contribute, the game updates itself.

The game lives beside the codebase under `game/`:
`index.html` (client) + `levels.json` / `levels.js` (the 100-level table,
generated by `tools/generate_levels.py`).

---

## 2. Core loop

1. **Act** — open/close issues, review PRs, merge code, improve docs, ship a
   release, add tests, or surface a telemetry bug.
2. **Capture** — a GitHub webhook (or scheduled Actions job) fires and posts the
   event to the tracking backend.
3. **Score** — the backend applies the points table (§4) to the contributor and
   recomputes their level from `levels.json`.
4. **Reflect** — the HTML5 client polls the leaderboard API and animates the new
   level, badge, privilege, or prize unlock.

No human curator is involved; the pipeline is the single source of truth.

---

## 3. Levels & tiers (100 total)

Levels are defined by a gentle rising XP curve so early wins feel fast while the
summit stays aspirational:

```
cost(L -> L+1) = 100 + 20·(L - 1)            # XP to advance one level
cum_xp(L)     = 100·(L-1) + 10·(L-1)·(L-2)   # total XP to *reach* level L
```

Reaching **level 100 requires 106,920 XP**. The ladder is grouped into **10 tiers
of 10 levels**, each tier a status rank:

| Levels | Tier | Rank |
|-------:|------|------|
| 1–10  | Initiate Researcher | Bronze |
| 11–20 | Lab Technician | Silver |
| 21–30 | Associate Engineer | Silver II |
| 31–40 | R&D Specialist | Gold |
| 41–50 | Senior Contributor | Gold II |
| 51–60 | Principal Innovator | Platinum |
| 61–70 | Research Lead | Platinum II |
| 71–80 | Distinguished Architect | Diamond |
| 81–90 | Fellow of the Body | Diamond II |
| 91–100| Chief Surrogate Architect | Legend |

Every level grants a cosmetic **research badge** (tier + level frame) shown on
the contributor's profile and in the `README` hall of fame.

## 4. Automatic points table

| Action | XP | Notes |
|--------|---:|-------|
| Issue opened | 10 | |
| Issue triaged / closed | 15 | |
| Documentation improved (`docs/`, `*.md`) | 15 | |
| Code review approved | 20 | |
| Tests added | 25 | scaled by test count |
| Telemetry / bug found via `telemetry()` | 30 | |
| Pull request merged | 50 | +1 per file touched, capped |
| Release shipped | 100 | |

Fraud hygiene: XP is credited only from merged/accepted events on the protected
`master` branch; force-push rewrites and self-merged trivial PRs are rate-limited
(per-contributor daily cap proposed at 400 XP).

## 5. Unlockable status, privileges & prizes

**Repo privileges** unlock at milestone levels and grant **real** capabilities —
the game doubles as a merit-based permission system:

| Level | Privilege |
|------:|-----------|
| 20 | Label & assign issues |
| 40 | Join the triage team |
| 60 | Write access to `examples/` |
| 80 | Merge rights on `docs/` |
| 100 | Architect seat (roadmap vote) |

**Prizes** land on five milestone levels:

| Level | Kind | Prize |
|------:|------|-------|
| 10 | Digital | Animated contributor badge + `README` hall-of-fame entry |
| 25 | Physical | New Body enamel pin + sticker pack |
| 50 | Physical | Embroidered lab hoodie |
| 75 | Physical | Mechanical keyboard + Cat-8 dev kit |
| 100 | Legend | Name etched on the chassis plaque + rig build tour |

All 100 rows (including per-level badge names) are emitted by
`tools/generate_levels.py` into `game/levels.json` and `game/levels.js`.

## 6. HTML5 implementation

**Client (`game/index.html`)**
- Pure vanilla HTML5 + Canvas-free DOM (no build step, no dependencies).
- Loads `levels.js` (`window.LEVELS`) so it runs from `file://` or any static
  host — no CORS, no server required for the prototype.
- Renders: live stats, a 100-cell progression track (milestones gold), the
  current unlock, and earned prizes/privileges. Persists local XP in
  `localStorage` for offline preview.
- Prototype includes "contribution" buttons that add the §4 XP values, exactly
  mirroring how the real pipeline would credit them.

**Backend (reference architecture)**
- **Capture:** GitHub webhooks → `POST /events` (or a cron GitHub Action using
  the REST/GraphQL API to diff since last run).
- **Score:** idempotent event store keyed by `(repo, actor, event_id)`;
  recompute cumulative XP and level against `levels.json`.
- **Store:** any KV/SQL (leaderboard table: `actor, xp, level, updated_at`).
- **Serve:** `GET /leaderboard` + `GET /contributor/:login` returning the
  current level, tier, rank, and unlocked reward lists.
- **Surface:** the HTML5 client polls `/contributor/:login` on load and after
  each detected event; `README` hall-of-fame is regenerated by the same job.

**Deployment:** static host (GitHub Pages / any CDN) for the client; the scoring
service is a small serverless function. The 100-level data file is the shared
contract between generator, client, and backend, so balancing changes only
require re-running `tools/generate_levels.py`.

---

## 7. Anti-abuse & fairness

- Only protected-branch, accepted events count.
- Daily per-contributor XP cap (proposed 400) prevents grind spikes.
- Privilege unlocks are auditable: the backend emits a signed record per grant.
- Tiers are monotonic — a level is never lost — but prize fulfillment is
  one-time per milestone.

---

## 8. Roadmap

- **Multiplayer:** team quests (e.g., "ship the human-twin release" bonus XP).
- **Streaks:** consecutive-week contribution multipliers.
- **Achievements:** hidden badges for first raw-frame contribution, first Rust
  port, etc.
- **Live board:** WebSocket feed so the HTML5 client updates the instant a
  teammate levels up.
